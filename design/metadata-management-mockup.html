Fields live in the contextual rail where the library keeps its own lists — title fields, your fields, and the chapters' language and group — each with how many distinct values it holds. Scope is the library's filter grammar, verbatim; opening the view from the library's select mode replaces it with "37 selected titles". The scope box says how many titles are in reach, and the values list counts only those.

The preview is the computation. It is worked out from the index before a single file is opened — which is also why it is instant on a large library. The run then costs one write per title that actually changes (508 writes), never one per title in scope, and leaves the shelf's "updated" order alone. Values typed by you are counted apart: an operation is your decision, so it changes them — the preview makes sure it is a decision.

RULE column: a value a rule already handles says so (→ romance · rule 1), and No rule narrows the list to the drift nothing catches yet.

A type change moves files, so its preview says how: a whole shelf renamed into a type that has no shelf yet is one directory rename; a filtered scope, or a merge into a type that already has a shelf, moves each title's directory onto the target shelf (a rename within the vault — no bytes copied) and sweeps a shelf left empty. Type changes run last, after every in-place change of the same run.

Moving into a single-value field fills it only where it is empty; where it already holds something else the two answers are listed, never decided silently.

Applies to capture, to what you type in the editor, and to chapter values on their way in. Saving it changes nothing already stored.

Order matters and is yours — drag a rule up or down. Rules run top to bottom in one pass: each sees what the earlier ones made, none re-fires on its own output, so two rules can never loop. A rule is disabled, not deleted, when you want it out of the way. Matching is on the whole value, after the cleanup capture already does (counts stripped, case folded where the field folds it).

Apply to existing titles opens the same preview as an operation (block 1): a rule never rewrites what is stored by itself. Fired counts how often the rule changed something, so a rule nothing triggers any more is visible.

Revert restores only values that still hold what the run wrote — a later edit is never rolled back, and the preview says how many no longer can be.

The journal lives in index.db, in a table of its own written in the same transactions as the index rows — no extra files, no extra I/O. A rebuild or an index upgrade leaves it alone; only deleting index.db loses it, and then what is lost is the ability to undo, never content.
