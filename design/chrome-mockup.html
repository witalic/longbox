Window chrome — v2 · «frame + card»

A different idea, not a formalization of the status quo: no chrome lines at all. The top band, the nav rail, the filter rail and the bottom gutter are ONE dark surface — a frame. The content floats inside it as a lighter rounded card on an 8px gutter. Separation comes from surface contrast; the only hairline left in the story is the card's own footer.

A · The full window

Tabs are quiet pills (the active one takes the card's color, tying it to the page below). The nav rail ends with the library status + theme toggle — no bar, no border. The filter rail is part of the frame: translucent search, indented rows, zero boxes. Pagination lives in the CARD's footer — where the data is, not in window chrome.

D · Decisions

  • Zero chrome lines. The frame (top band + nav rail + filter rail + gutters) is one surface. No H1/H2/V1/V2, no footer bars, no border management — the card's 8px gutter IS the separation. The only hairline is inside the card (its footer, list rows etc.).
  • The content is a CARD: rounded 10px, lighter surface, subtle ring + shadow, 8px gutter on the right/bottom/left. Title, Reader, Settings, Sources — every view renders inside the same card, so all screens are consistent by construction.
  • Tabs are pills, not fake browser trapezoids: inactive = ghost text + swatch, hover = faint wash, ACTIVE = the card's color, visually fusing the tab with the page below it. Pinning and close behave as now.
  • ˅ = system family: 46 × band cell, native hover wash, flush with −. The empty band stretch drags the window.
  • The nav rail ends with the status line (● Local library · ☾ theme) as plain rail content — no bar. The filter rail loses all boxes: translucent search field, breathing sections, indented rows.
  • Pagination belongs to the data: the card's footer row (range left, pager right). Views without lists have no footer — and that's consistent, because the footer is part of the card, not of the window.
