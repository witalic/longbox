Subtitles, and the downloads nobody armed

A file the browser downloads with nothing armed is no longer thrown away: it lands in the library's own downloads folder. An episode keeps its subtitles — added from that folder, from a file, or by arming the episode and downloading them — and the player shows them. Concept: design/subtitles.md.

Viewing stays as it is: the row says CC EN · UK, and the player's own CC menu switches the tracks — on the title page and in the reader.

In edit mode an episode's row gets a CC action beside Edit entry and Attach. It opens a small form under the row, the way Edit entry does: the tracks it has (default, make default, remove) and one to add — a file dropped on the form or picked, or one from the library's downloads (subtitle files, newest first, the one whose name carries this episode's number on top, its language read off the name). Stored as WebVTT, which the player shows: SRT converted, ASS flattened to text — the original kept beside it (D3).

Nothing armed, nothing lost: a file the library can use goes to <library>/downloads/ — beside the shelves, never read as one (D1) — with where it came from. It moves with the library. Attaching happens where the file belongs: an episode's Subtitles block, or an entry's Attach a file, which lists these too.

3 · DECISIONS

Four choices, each with a proposal

D1 · THE FOLDER
downloads in the library

Decided. A name a file manager shows — a share hides dot names. Never read as a type shelf; a type called that gets downloads-shelf.

D2 · WHAT IT KEEPS
Only files the library can use

Proposed. Subtitles, archives, images, videos; an installer or a script a page pushes is refused. The other way: everything a site sends.

D3 · THE ORIGINAL
Kept beside the WebVTT

Proposed. ASS styling is flattened for the player; the original stays for a styled renderer later. The other way: only the WebVTT.

D4 · AN ARMED EPISODE
Takes a subtitle file as its subtitles

Proposed. Arm the episode, download its subtitles — done. The other way: an armed download only ever replaces the entry's file.
