Nothing is written until Import. The scan reads the tree once; every change on the left re-plans from that scan and the library's current titles — no disk access per keystroke. Untick a work or an entry to leave it out; that choice belongs to this run, not to the profile. 2 · ONE TREE, TWO READINGS

Nested folders are not special: they are a role

L1 Creator · L2 Worktwo works, one creator
L1 Work · L2 Partone work, two sections

A part is anything that divides a work — a volume, a season, a year, a batch. Levels deeper than the last one with a role are parts too, so a tree where one work holds its videos directly and the next one holds 2025.1/ 2025.2/ needs no special case. Numbers run through the whole work and never restart per part: two "episode 1"s in one work would be one entry. A part becomes the entry's section — a field of its own, by which the title page groups entries; the contents editor sets it too.

Copy mode — the originals are where they were.

Works go one at a time, each under its own lock, and every file goes through the same ingest as a download — zip invariant, faststart, ComicInfo, a sidecar stamped from the stored file. Stop lets the file in flight finish: the vault never holds half an entry. Each entry remembers where it came from (origPath, origSize), so running the same import again skips what is done — that is also how an interrupted run resumes. In Move mode an original is deleted only after its entry is stored; on the vault's own drive the move is a rename and copies nothing.
